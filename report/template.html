Onda vs Faust

%%NPROG%% DSP programs written equivalently in Faust and Onda, from oscillators to reverbs, measured on a common harness against 13 Faust configurations. The Onda compiler generates very good native code: against Faust 2.95.1 (C++ and LLVM, every option), it is on average %%GSO%%× faster under strict IEEE semantics and %%GFO%%× faster with fast-math. The -lang ocpp backend of the master-dev-certification-4 branch, tuned by fcautotool, puts Faust ahead: onda ×%%GS%% strict and ×%%GF%% with fast-math.

The gaps follow the kind of computation: onda dominates as soon as it vectorizes (oscillator banks, saturation), Faust cert-4 dominates delay lines and filter cascades, where it chooses the order of operations and reads delays ahead. Two onda pitfalls, easy to avoid once known, cost a factor of 30 to 50: the ins[i]/outs[i] views, and control-rate computations left in the per-sample loop.

What the generated code shows

Where onda wins

additive64 ×3.4, tanh_drive ×1.6 (strict)

Vectorization and built-in SLEEF

Written as arrays, the 64 partials of additive64 are updated in SIMD and go through Sleef_sinf4 (16 calls instead of 64 sinf): 34 ns with fast-math against 152 for the ocpp pick and 81 for the best Faust build (-vec + Accelerate). tanh_drive goes through Sleef_tanhf4. The Faust C++ backends call scalar libm, and their -vec mode does not vectorize a phase recurrence.

noise ×2.6, zita_rev ×2.1 against -lang cpp

State in registers, Hadamard kept whole

onda loads the state on entry to onda_process and writes it back on exit (noise loop: 8 instructions, 1 memory access). -lang cpp copies every fRec[0]/[1] through memory at each sample: moving the noise recursion into a local variable takes the C++ from 3.20 to 1.20 ns. On zita_rev, the normalizer flattens the allpasses into the Hadamard (16-term sums, ~120 additions instead of 32): 570 instructions per sample against 236. ocpp fixes both: 1.33 ns on noise, 10.7 on zita_rev with fast-math against 10.4 for onda.

Where Faust wins

freeverb ×2.4, fdn8 ×2.3

Delay lines read one sample ahead

ocpp reads the next sample's delay line at the end of the current iteration (fTemp0 = fVeeec0; fVeeec0 = buf[(IOTA-224)&255];), which takes the load latency off the critical path, and keeps the state in scalars with a single masked IOTA. freeverb: 2.73 ns against 6.47 for onda, which recomputes a circular index per line. fdn8, with the -ls-fuse -ls-sched model pick: 2.34 ns against 5.38.

peq10 ×1.6 strict, biquad8 ×1.5

Order of operations and signal algebra

On peq10, ocpp merges the stages (a stage's input memory is the delayed output of the previous one) and writes fSlow13·y[0] + (past terms): a single multiply-add per stage on the critical path. 5.22 ns in IEEE and 3.48 with FMA contraction, against 8.47 for onda, which follows the source order and may not change it in strict mode. With -ffast-math, clang undoes that order (9.85 ns). On biquad8, Faust recognizes b2 ≡ b0 and factors it: 2.77 ns with fast-math against 4.23.

diffuser32 ×1.3 strict, ×1.9 at best

Stage by stage rather than sample by sample

Faust -vec computes each allpass over 32 samples before moving on to the next; since the delays (≥ 113) exceed the vector size, the iterations of a stage are independent and the processor overlaps them: 15.9 ns in IEEE. The -lang ocpp -temp 4 -ls-fuse -ls-sched model pick goes down to 11.5 ns. onda (21.4 ns) chains the 32 stages for every sample, a 32-link serial chain.

fm_pad ×2.2

Split loops and vector libm

Faust -vec puts the four phase recurrences in short scalar loops and the 4 sin + 2 tanh in a recurrence-free loop, which clang vectorizes with Accelerate's vsinf/vtanhf: 6.4 ns against 14.2. onda keeps a single per-sample loop: the recurrence blocks vectorization and SLEEF does not come into play. Without Accelerate, no Faust configuration beats onda.

clarinet ×1.3 strict, ×2.0 fast-math

A complete physical model

pm.clarinet_ui_MIDI ported line for line (reed table, two-way bore with 4th-order Lagrange fractional delays, bell reflection, blower with vibrato table oscillator and filtered breath noise): onda reproduces the Faust output to 5·10⁻⁷ relative RMS. onda (10.9 ns) is level with -lang cpp (10.7), ocpp is faster: 8.0 ns in IEEE, 6.1 with fast-math. Both loops have ~205 instructions, but onda makes twice as many memory accesses (47 against 26, struct state and the local tap array). With --fast-math, onda gets slower (12.2 ns).

frenchbell ×1.5 strict, ×1.7 fast-math

A modal bank rolled into a loop

pm.frenchBell_ui: 50 pm.modeFilter resonators in parallel, excited by a filtered noise strike. onda, with the modes written as arrays, vectorizes their update and beats -lang cpp 2.6× (18.7 ns against 48.2). ocpp recognizes the 50 filters as a family of identical structures, rolls them into a loop over coefficient tables and splits the long sum into 4 interleaved partial sums: 12.8 ns in IEEE, 8.1 with fast-math. onda, in strict mode, must keep the 49 additions of the sum in order; written by hand with 4 partial sums (variant frenchbell_x), it reaches 16.3 ns.

violin ×1.2 strict, ×1.3 fast-math

Bowed string

pm.violin_ui_MIDI: two string segments of two fractional delay lines each, nut and bridge reflection filters, bow table, body resonator. onda reproduces Faust to 6·10⁻⁷ and takes 24.4 ns against 21.1 for -lang cpp in IEEE, 20.1 against 15.8 for -vec + Accelerate with fast-math. The faust of the certification-4 branch rejects this program with the current libraries (the interval analysis cannot bound the de.fdelay4 index in the string loop, the official violinMIDI.dsp included): its columns are empty.

fir32c ×1.2

Constant-tap FIR

onda 4.43 ns against 3.71 for ocpp IEEE: the taps are reloaded from memory even from a const array, and the strict sum starts with 0.0 + …, which IEEE forbids folding (−0). With fast-math the two meet (3.81 against 3.75).

Writing pitfalls on the onda side

hoa_decoder: ×50 → ×1.7 strict

The ins[i]/outs[i] views

Written with ins[j]/outs[k], as onda's documentation shows, every access becomes a tree of comparisons and fcsel; nothing is unrolled or vectorized: 32 ns against 0.65. With named ports gathered in a local array, onda vectorizes: 1.10 ns strict, 0.67 with fast-math, on par with Faust. The remaining strict gap comes from the 16 zero coefficients of the matrix: Faust removes them, LLVM may not in IEEE (x·0 is NaN or −0).

mixer16: ×40 → ×1.1 strict

Control-rate computations left in the loop

pow, cos, sin of parameters written in sample: stay per sample (16 powf + 16 sincosf); Faust computes gain·pan·master once per block. With the coefficients in block: and named ports, onda takes 1.34 ns strict (1.22 for ocpp) and 0.93 with fast-math, ahead of Faust (1.19).

Fixed SR: ±4 %

Fixing the sample rate changes almost nothing

With SR = 48000.0 in platform.lib, Faust folds the constants that depend on fSampleRate, but those computations already ran once at init or once per block. Differences ≤ 4 %, except zita_rev (−6 % for Faust LLVM, +15 % for the pick) and peq10 (ocpp IEEE −10 %, pick +8 %). onda gets no measurable advantage from compiling the sample rate in.

Floating-point contract

Comparing like with like

onda emits neither FMA contraction nor reassociation without --fast-math. Apple clang contracts into FMA by default (-ffp-contract=on), which sometimes changes the result a lot (peq10 ocpp: 3.48 ns with FMA, 5.80 without), and Faust LLVM marks every operation reassoc nnan ninf nsz arcp contract. Hence the IEEE columns at -ffp-contract=off, and Faust LLVM ranked with fast-math.

onda's implementation

Proven bounds, JIT = AOT

What works well

No index clamp in the loops of fir, fdn8 and zita_rev: the {N, wrap} domains and the MIR bounds proofs remove the checks. State arrays vectorize (SLP across the 8 damping filters of zita_rev). The AOT object and the ORC JIT give the same times within 5 %. Compilation: 40 to 80 ms (full CLI) against ~1 s for faust + clang -O3 and 5 to 70 ms for the Faust LLVM JIT.

Rough edges

Language and build

No scientific-notation literals (1e-20 is rejected). The build requires exactly LLVM 21, and the target.cpp shim initializes every target of the LLVM installation: linking fails with a distribution LLVM (AMDGPU…), a prefix limited to 4 targets was needed. LLVM 21 does not know the Apple M5: onda targets apple-m4.

Options elected by fcautotool

On each program, fcautotool races the ocpp option sets the cert-4 faust accepts, plus -lang cpp, -vec and -mcd 0 as references, timed with -O3 -ffast-math -mcpu=native, and only elects a candidate that reproduces the reference response. These options are used in the "fcautotool pick" column.

The compiler in brief

onda is a Rust compiler of about 400,000 lines. The frontend (PEG grammar) and the semantic analysis (typing, overloads, generic specialization, lowering of processors and graphs) produce a typed, validated MIR: structured control flow, explicit storage and effects, integer range facts, bounds proofs, memory origins for aliasing, loop analyses. Two backends consume it: LLVM (ORC JIT and AOT objects, O3, noalias attributes and alias scopes, 64-byte alignment, SLEEF linked into the code) and Binaryen (Wasm). Block size and sample rate are compile-time constants.

The code quality comes from these proofs handed to LLVM, not from DSP-specific optimizations: onda has no equivalent of Faust's signal normalization. The code therefore stays close to what the author writes. An array of delay lines gets vectorized, eight separate variables would not. Conversely, Faust optimizes forms the author did not factor, but can also undo a factorization (zita's FWHT).

Method

Machine
Apple M5, macOS 26.6, on AC power, thread at user-interactive QoS.
onda
0.9.2, built against MacPorts LLVM 21.1.8 (the project pins 21.1.2). AOT object --emit obj --target-cpu host -b 256 --sr 48000, with and without --fast-math, called through the raw ABI (onda_process).
Faust C++
faust -lang cpp 2.95.1 (-scal and -vec -vs 32) with the libraries of the faustlibraries checkout, Apple clang -O3 -mcpu=native, three contracts: default (FMA), -ffp-contract=off, -ffast-math; plus -vec with -fveclib=Accelerate.
Faust LLVM
libfaustwithllvm (2.95.1), createDSPFactoryFromFile, opt −1 (max), -scal and -vec -vs 32, plus -scal with a fixed SR.
Faust cert-4
Branch master-dev-certification-4 (106dda74a, 2.92.5), exported with git archive and built with the Makefile of build/. -lang ocpp in IEEE (-ffp-contract=off), with the default contract and with -ffast-math; options elected by fcautotool compiled with -O3 -ffast-math, as during the election.
Fixed SR
Copy of the faustlibraries libraries where platform.lib defines SR = 48000.0 (faust looks for platform.lib next to maths.lib first, hence the full copy).
CPU targets
onda (LLVM 21) and Apple clang 21 target apple-m4: LLVM 21 does not know the M5. Only the Faust LLVM JIT, built with a newer LLVM, targets apple-m5.
Harness
One executable per program links the 15 engines, with 16 input and output channels; same buffers, same input (deterministic white noise, 64 blocks cycled), 2000 warm-up blocks, then 21 rounds in shuffled order. Median reported; median absolute deviation below 2 % except additive64 (~2 %).
Corpus
%%NPROG%% hand-written programs, same algorithm in both languages (same equations, same delay lengths, same order of operations where possible), part of them chosen to exploit a Faust lever (loop splitting in -vec, control-rate computations lifted out of the loop, zero or repeated constants, many delay lines). Three alternative onda writings (fir32, hoa_decoder, mixer16) separate what belongs to the compiler from what belongs to the writing. zita_rev ports exactly re.zita_rev1_stereo(60, f1, f2, t60dc, t60m, 48000) of the checkout. Real idiomatic versions differ: in Faust, an oscillator would use os.osc (table), not sin.
Limits
A single machine (ARM64, 128-bit NEON); on x86 AVX2/AVX-512, the SLEEF gap should grow and the SLP gap change. Constant parameters (no automation). A single block size.
