The compilers in brief

Faust compiles a functional block-diagram language: the program is normalized as a signal algebra (common subexpressions, constant folding, delay sharing), then scheduled into C++, LLVM IR and other targets. The certification branch adds the -lang ocpp backend, with loop scheduling, fusion and register promotion options that fcautotool elects per program.

Onda is a Rust compiler of about 400,000 lines: a typed, validated MIR with integer range facts, bounds proofs and aliasing information, lowered to LLVM (ORC JIT and AOT objects, SLEEF linked into the code) or Wasm. Block size and sample rate are compile-time constants. Its code quality comes from these proofs handed to LLVM, not from DSP-specific rewriting: the code stays close to what the author writes.

Cmajor compiles processors and graphs with typed endpoints, either to C++ (cmaj generate) or through its own LLVM JIT (libCmajPerformer), which knows the sample rate at build time. The runtime advances one frame at a time and exchanges audio by copies.

YDSP, in YUP's yup_dsp_jit, compiles Cmajor-style processors and a Faust-style graph algebra at load time with asmjit, without LLVM: compilation takes about a millisecond. Its optimiser hoists parameter-only expressions, keeps scalar state in registers, proves ring indices in range and widens qualifying loops to 4 lanes, with SLEEF for vectorized transcendentals under fastMath.

C++, the baseline: the same programs written by hand as plain C++17 classes (dsp/NAME.cpp), the way a DSP developer writes them for speed while staying ordinary code: coefficients recomputed outside the sample loop, state loaded into locals for the block, delay lines with a wrapping index; no intrinsics, pragmas or libraries. Compiled by Apple clang, like the generated C++ of Faust and Cmajor.

Method

Scheduling
The harness requests user-interactive QoS on macOS.
Onda
AOT object --emit obj --target-cpu host -b 256 --sr 48000, in strict and fast-math modes, called through the raw ABI (onda_process).
Faust C++
faust -lang cpp 2.95.3, master-dev 0b21bae83 (-scal and -vec -vs 32) with the libraries of the faustlibraries checkout, Apple clang -O3 -mcpu=native, three contracts: default (FMA), -ffp-contract=off, -ffast-math; plus -vec with -fveclib=Accelerate.
Faust LLVM
libfaustwithllvm (2.95.3), createDSPFactoryFromFile, opt −1 (max), -scal and -vec -vs 32, plus -scal with a fixed SR.
Faust cert-7
Branch master-dev-certification-7 (7db0ae9cd, 2.94.1), exported with git archive and built with the Makefile of build/. -lang ocpp in IEEE (-ffp-contract=off), with the default contract and with -ffast-math; options elected by fcautotool compiled with -O3 -ffast-math, as during the election.
Cmajor
1.0.3209. cmaj generate --target=cpp --maxFramesPerBlock=256, class renamed per variant, compiled by Apple clang -O3 -mcpu=native (IEEE: -ffp-contract=off; fast: -ffast-math), audio exchanged through setInputFrames / advance / copyOutputFrames; the sample rate is a run-time value. JIT: libCmajPerformer.dylib, cmaj::Engine "llvm", optimisation level 3 and 4 (fast maths), sample rate given at build time (BuildSettings::setFrequency), so constant like Onda's. Parameters are input event endpoints whose handlers recompute the derived coefficients: Cmajor's way to keep control-rate math out of the sample loop (the generated C++ also ignores the init annotations of input value endpoints).
YDSP
YUP yup_dsp_jit, built with YUP's CMake as a static library behind a C interface (tools/ydsp/). YdspCompiler::compile on the host target (automatic tier, NEON, 4 lanes), fastMath false and true; YdspAudioGraph::process per 256-frame block. Parameters are sampled once per block and the parameter-only expressions are hoisted out of the sample loop by the optimiser; the sample rate is a run-time value.
C++
Hand-written port, compiled inside a namespace with Apple clang -O3 -mcpu=native (IEEE: -ffp-contract=off; fast: -ffast-math); prepare(48000) at init, so the sample rate is a run-time value, then process on the harness buffers in place. Parameters are members whose setters recompute the derived coefficients.
Fixed SR
Copy of the faustlibraries libraries where platform.lib defines SR = 48000.0 (faust looks for platform.lib next to maths.lib first, hence the full copy).
Harness
One executable per program links the available engines, with 16 input and output channels; same buffers, same input (deterministic white noise, 64 blocks cycled), 2000 warm-up blocks, then shuffled, interleaved rounds. The reported timing is the median.
Corpus
%%NPROG%% programs in four languages and C++, same algorithm in each (same equations, same delay lengths, same order of operations where possible). Eighteen were written for the benchmark, part of them to exploit a Faust lever (loop splitting in -vec, control-rate computations lifted out of the loop, zero or repeated constants, many delay lines); twenty reproduce examples of the Faust distribution with their default settings (bypass dropped, gates held at 1; four defaults changed where they made the program trivial: pitch_shifter, autopan, tapiir, and noise_gate kept but open). Four alternative Onda writings (fir32, hoa_decoder, mixer16, frenchbell_x) separate what belongs to the compiler from what belongs to the writing. Each port takes the form its compiler handles best while staying ordinary code in its language; the greyhole ports pad their 24 delay lines by 16 floats to avoid L1 cache-set conflicts, a memory-layout choice Faust's C++ does not make.
Limits
A single machine (ARM64, 128-bit NEON); on x86 AVX2/AVX-512, the SLEEF gap should grow and the SLP gap change. Constant parameters (no automation). A single block size.
